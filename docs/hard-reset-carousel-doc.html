Component Spec · Section 02

Join the Party — Carousel

The Coverflow flier carousel and its expanding terminal detail view. This reference reflects the current build: staged clear-out with a collapsing active card, real-text binary corruption, the beam-free CRT expand, the share button, and the flier-hero details layout.

01Overview

Section 02 presents upcoming and past parties as a stack of fliers in a 3D Coverflow. One flier is active (front-and-center); the rest fan back on either side, angled and dimmed. Selecting the active flier boots a terminal window that powers on like an old CRT, revealing the event's details and lineup.

The whole component lives inside one scroll-snap deck slide and is fully self-contained — no external libraries. All 3D positioning, navigation, and the detail animation are hand-rolled CSS transforms + a small amount of JS.

03Navigation

No arrows. The carousel is driven three ways and behaves like a proper one-at-a-time carousel:

Method A

Click an inactive card

Clicking a neighbouring flier promotes it to active; the stack re-flows toward it.

Method B

Horizontal trackpad scroll

A two-finger horizontal swipe advances exactly one flier. The gesture locks on the first move and unlocks only once the wheel events (incl. momentum) stop — one swipe = one item.

Method C

Pointer drag

Click-drag left/right past a small threshold steps one flier, for mouse users.

Open

Click the active card

Clicking the already-active flier opens the terminal details view (Section 06).

04Active card frame

The active flier is framed with a 1px border and an even 8px gap between the image and that border on all sides. The border fades from transparent to green as a card becomes active.

Because the site uses box-sizing:border-box, the padding and border are drawn inside the card's existing width — the outer box stays the same size. Since the Coverflow's spread, depth, and rotation all derive from that outer width, the 3D effect is completely unchanged, with no size-pop when a card activates.

05Caption

Below the stage, the caption reads out the active event as three stacked lines: Date (cyan), Venue (white), and a colored status tag — magenta TICKETS LIVE, red SOLD OUT, grey PAST, amber EARLY BIRD.

SAT · OCT 17 · 2026
[UNDISCLOSED WAREHOUSE] · SF
TICKETS LIVE

On open, the caption's real characters (date + venue) corrupt into random 0/1 in place — each character flips to binary at its own random moment, shimmering as it goes. The status tag is not scrambled; the whole caption (including the tag) then fades out together as the details animate in.

06Details view — terminal window

07Open animation — staged clear-out + CRT power-on

Opening is a deliberate two-phase sequence. First everything around the flier clears out; then the terminal screen powers on. There is no beam flash — the screen just expands with a soft green edge glow.

BeatWhat happensTiming
1 · Inactive fadeThe side flier cards fade out completely first.0 → ~0.3s
2 · Active collapseThe active flier collapses — it squishes vertically (scaleY→0, green frame and all) down to a horizontal line, rather than fading.~0.34 → 0.78s
3 · Caption corruptThe real date + venue characters scramble into random binary in place; the status tag stays intact.0 → ~0.4s
4 · Screen expandsThe terminal screen expands vertically from a center line to full height (full width throughout) with a soft edge glow.~0.92 → 1.55s
5 · Fade outAs the screen animates in, the whole caption (incl. availability tag) and the section heading fade out together.~0.84 → 1.26s

The screen starts at scaleY(0) — full width, zero height — anchored to viewport center, so it grows symmetrically up and down. The expand is triggered a frame after the overlay is shown (to escape the display:none transition trap) and is delayed so it fires only after the clear-out. The backdrop is transparent — the glitch and the live binary background stay visible behind the window.
